v1.0.8
==================================
BlackQuill is now open source under the MIT License, and the SRD data is no longer included (users import it themselves).

Licence
- LICENSE is now the standard MIT License, Copyright (c) 2026 Phil Davidson. It replaces the all-rights-reserved proprietary licence: anyone may use, copy, modify, publish, distribute and sell BlackQuill as long as the copyright notice and licence text stay with it.
- package.json, client/package.json and both package-lock.json files say "license": "MIT" (was "UNLICENSED").
- The notice on the login page and in the Admin Console now reads "© 2026 Phil Davidson. MIT License." (was "All rights reserved.").
- README.md's Licence section is rewritten to match.

SRD
- The srd-data folder (about 4 MB of D&D 5e SRD 5.1 JSON) is removed from the package and the repository.
- The SRD page offers a DM three ways to bring it in: "Download SRD 5.1 from GitHub" (5e-bits/5e-database), "Upload JSON files…" (pick the 25 files from your computer; 5e-SRD-Spells.json or Spells.json names both work), and "Import from folder", which appears when the files are in blackquill-common-data/system/srd/import/ (or srd-data/5.1/ in the BlackQuill folder, as before).
- Until it is imported, the app works as normal; the SRD page shows these choices to DMs and tells players to ask their DM.
- An SRD you already imported (in blackquill-common-data/system/srd/) is kept and keeps working; nothing to do after upgrading.
- Changed: server/lib/srd.js (folder and upload sources, status adds localAvailable, importFolder, requiredFiles), server/routes/srd.js (new POST /api/srd/import-files), client SrdBrowser.jsx (import screen), styles.css (.srd-import-help), client/src/utils/copyright.js (MIT notice), rebuilt client/dist; LICENSE, README.md, GITHUB.txt examples; version 1.0.8.

v0.86.3
==================================
Clean-up release: less code, two security fixes, current libraries. Nothing changes in how BlackQuill looks or works for DMs and players, apart from the fixes below.

Security fixes
- Anyone, without logging in, could download any file in the data folder through the login banner address (for example /api/template/assets/..%2F..%2Fusers.json returned every account with its password hash). The banner address now only serves the banner.
- A player could read a note's DM Secrets by asking for dm-secrets.md as if it were a picture (/api/notes/<campaign>/<note>/asset/dm-secrets.md). The picture address no longer serves .md files.
- If you exposed v0.86.2 or earlier to people you do not trust, consider changing passwords.

Fixes
- Settings › Navigation: a menu or subcategory you switched off disappeared from the editor after a reload, so you could not switch it back on, and the next Save dropped it from navigation.json. The editor now loads the full configuration (GET /api/navigation/admin) and keeps disabled items.
- Admin Console: "User created." and "Admin banner uploaded and selected." disappeared the moment they appeared. Messages now stay until you do something else.
- Debug logging in the browser now also works for players when debug is on (GET /api/debug-status returns { forced, enabled }).

Removed (dead code and finished one-time patches)
- The v0.84 data migration (server/lib/migrate.js) and the old v0.83 paths. Data still on the v0.81–v0.83 domains layout must be started once with v0.86.2 first; it converts the folder and takes a backup.
- Old category names from before Adventure Groups ("The Party", "The Adventurers", "Characters", "City/Town" and so on) are no longer translated.
- The Google Drive storage-provider stub (server/lib/storage/), which nothing called.
- Unused server endpoints: GET /api/template/style, GET and POST /api/template/settings, GET /api/admin/users, POST /api/admin/banner (the Admin Console now uploads through POST /api/template/banner, the same route as DM Settings).
- BlackQuill no longer creates system/layout.json, system/templates/default/banner.svg, icon.svg and default-style.json (nothing read them). Existing copies are left alone.
- File Checker no longer warns about pre-v0.84 folders.
- Unused helpers and files: server/config.js, lib/filesystem/{assets,canonical,categories,templates}.js, client fallback category lists, unused CSS rules, an unused "icon set changed" event and debug-changed listener.

Simplified (duplicates merged)
- One place each for: login/role checks and the audit log (server/lib/auth.js), settings and banner names (server/lib/settings.js), copying folders (copyTree in fsdb.js), the debug switch (isDebugEnabled), the public user object, the note-folder rules, the note editor's starting form, the card text preview and the subcategory chips.
- The app version on the login page now comes from the server like the top bar.
- Audit log lines from the Admin Console now use the same fields as the rest ({ user, role, action }) instead of { admin, action }.

Libraries
- Server: Express 5.3 (was 4.18), bcryptjs 3.0, express-session 1.19, multer 2.5, slugify 1.6.9, concurrently 10. markdown-it and markdown-it-anchor removed from the server (only the client uses markdown-it).
- Client: React 19.3, Vite 8.3, markdown-it 15. Versions are pinned instead of "latest". @vitejs/plugin-react removed: there was no vite.config.js, so it was never loaded.
- Node.js 22.12 or later is needed (Node 24 LTS recommended). The Docker image now uses node:24-alpine.
- package-lock.json files regenerated from https://registry.npmjs.org/ only; npm audit reports 0 vulnerabilities.

v0.86
==================================
New entries: Forgotten Realms Wiki lookup, closest-match suggestion, and text + picture import.
- While you type a new entry's title, BlackQuill checks forgottenrealms.fandom.com (after you pause for about a second, 3+ characters). A "Forgotten Realms Wiki" panel under the Title shows the result:
  - an exact article ("Found Waterdeep", with Import). Redirects count, so "Elminster" finds "Elminster Aumar". Case does not matter.
  - no exact article: "No page called "Elminser". Closest match: Elminster Aumar", with Import this. The closest match is the wiki search's spelling suggestion if there is one, then title matches, then full-text search results.
  - other close matches as small buttons; clicking one puts its URL in the URL box so you can check it or import it.
  - always a box to paste a specific wiki URL, with Import URL (Enter works too).
- Import brings in the article text as Markdown: the infobox becomes a "Quick Facts" list, then the article's paragraphs, headings and lists. References, edit links, navigation boxes, tables, and the Appearances / Gallery / References / Further reading / External links sections are left out. A "## DM Notes" heading is added, then a "## Source" section with the attribution.
- Pictures: the panel shows the article's pictures (up to 8, icons and logos skipped), all ticked. Untick any you do not want. When you press Save, the note is saved first and then the ticked pictures are downloaded into the entry's own folder, next to its .md file (campaigns/<campaign>/notes/<category>/<subcategory>/<entry>/wiki-<name>.png). They appear in the entry's picture strip like uploaded images, with the article's captions. If a download fails the note is still saved and you get a message.
- Attribution (the wiki's text is CC BY-SA 3.0): every imported note keeps the article URL, title, licence and import date in its front matter (wikiSource) and in the Source section, and the reader shows "Source: <article> on the Forgotten Realms Wiki (CC BY-SA 3.0)" under the text. Each imported picture keeps the link to its File: page (its licence is listed there; many are copyrighted D&D artwork, so keep them for your table).
- Import asks before replacing text you have already written. "Undo import" puts the note back. The title is only filled in if it was empty.
- Safety: lookups and imports now need a login (the old import route did not check). Pictures are only downloaded from the wiki's image server (static.wikia.nocookie.net), images only, 10 MB maximum each. Imported text cannot inject HTML into the reader.
- Replaces the v0.59 page-scraping import (which only took the first 8 paragraphs, guessed the URL from the title and took no pictures). Uses the MediaWiki API (query, opensearch, search, parse, imageinfo).
- API: GET /api/import/forgotten-realms/lookup?name=, GET /api/import/forgotten-realms?url= (or ?name=), POST /api/notes/:campaign/:slug/wiki-images.
- New server/lib/fandom.js; changed server/routes/import.js, server/routes/notes.js (wikiSource and image source kept on save; wiki-images route), client NoteEditor.jsx (wiki panel), NoteView.jsx (source line), styles.css (.wiki-* styles).
- Needs internet access from the BlackQuill server to forgottenrealms.fandom.com and static.wikia.nocookie.net. Without it the panel says it cannot reach the wiki and you can write the entry by hand.

- Takes a full copy of the data folder into system/backups/pre-v0.84-migration-<time>/ first.
- Merges system/admin-users.json, legacy users/users.json and every domain's users into system/users.json. Login name clashes between domains are renamed <name>-<domain>. Users in suspended domains are locked. Each migrated user keeps formerDomain for reference.
- Moves shared-assets/ and each domain's templates, styles, icons and banners into system/. Identical files are dropped; different files with the same name are kept as <name>-<domain> (icon packs as <pack>-<domain>).
- Moves each domain's campaigns to campaigns/<slug>/ (clash: <slug>-<domain>) and pre-v0.81 campaigns/data-campaign-<slug>/ folders to campaigns/<slug>/, and rebuilds campaigns.json. Each campaign gets a campaign.json with formerDomain and migratedFrom.
- Moves datasets/, backups/ and settings/navigation.json into system/.
- Archives anything left (domains.json, per-domain branding/domain.json) to system/legacy/v0.83/. Never deletes user data.
- Writes system/migration-v0.84-<time>.log and system/layout.json (layoutVersion 2). If a step fails, it stops, logs the error, and resumes on the next start.
- Debug mode (runme-debug.bat / --debug / BLACKQUILL_DEBUG=1) prints each migration step.
