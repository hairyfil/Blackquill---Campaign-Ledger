MASTER REBUILD PROMPT
VERSION: v0.87

Build a full-stack, production-ready, self-hostable web application called BlackQuill – Campaign Ledger.

Core stack:
- Backend: Node.js + Express
- Frontend: React + Vite
- Storage: filesystem only, no database
- Authentication: session-based login, bcryptjs only, no bcrypt

Current architecture (v0.84):
- Single instance, no domains. One login page for every account.
- Persistent data lives under ../blackquill-common-data/ (override with BLACKQUILL_DATA)
- The data folder has exactly two top-level folders: system/ and campaigns/

Admin account:
- No built-in default password. See V0.84.6 FIRST-RUN SETUP below.

Roles (all stored in system/users.json):
- admin: platform owner; opens the Admin Console; manages users, data sets, backups, settings
- dm: Dungeon Master; can create campaigns and notes, edit navigation and branding
- player: can view campaigns and notes; never sees DM Eyes Only or DM secrets

Folder structure:
blackquill-common-data/
  system/
    layout.json            { layoutVersion: 2, version, migratedAt? }
    users.json             all accounts (admin, dm, player)
    settings.json          debug, activeBanner, bannerWidth, activeStyle, activeIconPack
    navigation.json        menu/category configuration
    audit.log              admin actions, one JSON object per line
    templates/
      default/             intro.txt, banner.svg, icon.svg, default-style.json
    styles/                style .json files
    icons/
      default/             icon packs, one folder per pack
    images/
      banners/
    datasets/
      <dataset-slug>/      dataset.json + files to copy into a campaign
    srd/                   (v0.85) imported D&D 5e SRD, shared by all campaigns
      srd.json             manifest: edition, source, importedAt, importedBy, counts
      5.1/                 5e-bits JSON files (5e-SRD-*.json names without prefix), ATTRIBUTION.txt
    backups/
    legacy/                archived leftovers from older layouts
  campaigns/
    campaigns.json         campaign index
    <campaign-slug>/
      campaign.json
      notes/
      sessions/
      assets/

All paths come from server/lib/filesystem/paths.js (PATHS). Old locations are listed
only in LEGACY_PATHS and are read only by the migration.

Filesystem access goes through server/lib/fsdb.js helpers and server/lib/filesystem/ (paths,
campaigns, notes). There is no storage-provider abstraction (removed in v0.86.3; it was never used).

Campaign and note scoping:
- Campaigns are global to the instance; any DM or player sees all campaigns in campaigns.json
  plus any campaign folder found under campaigns/
- Campaign names and slugs are unique across the instance
- Notes, note images, dm-secrets.md and sessions resolve inside campaigns/<campaign-slug>/
- Campaign slugs from request URLs are sanitised (a-z, 0-9, -) before building paths

Existing BlackQuill feature set to preserve:
- Configurable navigation taxonomy
- Settings navigation enable/disable and reorder
- DM Eyes Only menu protected and DM-only
- Note cards in portrait layout
- The Adventure Groups / Groups / PCs model
- Note folders canonical: <note-slug>/<note-slug>.md

- Banner manager and banner width selector
- Style selector, icon pack selector, debug toggle
- YAML sanitization before save

V0.82 INSTALL, RUN AND DEBUG REQUIREMENTS:
- Windows setup uses three scripts in the project root:
  - install.bat: install/update only. Runs npm install, then npm audit fix, for the root/server packages and for client/, then builds the client. It must not start the app.
  - runme.bat: run only. Starts the server with node server/index.js (npm run server) and forwards any arguments. Refuses to start, with a message to run install.bat, if node_modules or client/dist/index.html is missing.
  - runme-debug.bat: same as runme.bat but starts with debug mode forced on.
- npm audit fix failures are warnings, not fatal errors. npm install and build failures stop install.bat.
- Debug mode can be forced on from the command line without logging in, via the --debug argument or the BLACKQUILL_DEBUG environment variable (1/true/yes/on). A forced debug overrides the saved admin debug setting for that run only and is never written to settings.
- The debug override lives in server/lib/debug.js (isDebugForced). Server startup, admin domain-asset copying and login must all honour it.
- When debug is forced, the server prints "DEBUG MODE FORCED ON" at startup.
- GET /api/debug-status (no login required) returns { forced: true|false }. The client turns on browser debug logging when either the saved setting or the forced flag is on.
- When debug mode is on (saved or forced), each login attempt is logged to the server console with the [BlackQuill DEBUG] prefix: login name, scope, requested domain, users files checked, whether an account matched, whether the password matched, and the outcome. Passwords and hashes are never logged.
- Password recovery without logging in: stop the server and either remove system/admin-users.json (a default admin/blackquill account is recreated at startup) or replace a user's passwordHash with a bcryptjs hash.

V0.84 DATA LAYOUT + DOMAIN REMOVAL (SUPERSEDES EARLIER DOMAIN RULES)
====================================================

Everything above or below that mentions DM domains, domain folders, shared-assets/,
global-settings.json, admin-users.json, /d/<domainSlug> logins, or top-level
datasets/ and backups/ folders is superseded by this section.

Layout:
- blackquill-common-data/ contains only system/ and campaigns/.
- system/ holds all system data, settings files, users, templates, styles, icons,
  general graphics (images/banners), datasets and backups.
- campaigns/ holds campaigns.json and one folder per campaign named by its slug
  (no data-campaign- prefix).

Login:
- POST /api/auth/login takes { email|username, password }. One users file, no scope.
- Locked users are refused. Admin role goes to the Admin Console.
- The login form does not pre-fill credentials.
- With debug on, each login attempt logs: login name, users file and account count,
  whether an account matched, whether the password matched, and the outcome.

Admin Console menu:
- User Management, File Checker, Data Sets, Backup / Restore, Settings, Logout.
- User Management: list all accounts, create dm or player accounts, reset password,
  lock/unlock, delete. Admin accounts are protected in the UI and enforced by the API.
  API: POST /api/admin/users, PUT /api/admin/users/:userId, DELETE /api/admin/users/:userId.
- Data Sets: pick a dataset from system/datasets/ and a campaign; copy every file and
  folder inside the dataset into campaigns/<campaign-slug>/. Debug logs source and target.
- Backup / Restore: full backup (everything except system/backups itself) or a single
  campaign, into system/backups/backup-<time>-all or -campaign-<slug>.
- File Checker: checks system files/folders, campaigns/, each campaign's notes folder,
  canonical <slug>/<slug>.md notes, and warns about leftover old-layout folders.
  Safe repair only creates missing folders.
- Settings: style, icon pack, banner select/upload/width, debug. Stored in system/settings.json.

Branding:
- One set of branding for the instance. /api/template/* and /api/icons read and write
  system/ only. Admin Settings and the DM Settings page edit the same settings.

Migration (server/lib/migrate.js, called first from initData()):
- Runs once when system/layout.json is missing or below layoutVersion 2 AND an old-layout
  item exists (domains/, shared-assets/, datasets/, backups/, settings/, users/,
  system/admin-users.json, system/global-settings.json, system/domains.json, or
  campaigns/data-campaign-*).
- Step 0: copy the whole data folder (except backups) to system/backups/pre-v0.84-migration-<time>/.
- Users: admin-users.json (role admin) + users/users.json + each domain's users.json into
  system/users.json; drop domainSlug/domainName; keep formerDomain; login clashes renamed
  <name>-<domain>; users of suspended domains locked.
- Settings: settings/settings.json + system/global-settings.json into system/settings.json
  (drop scope/domainSlug); settings/navigation.json to system/navigation.json.
- Assets: shared-assets/{templates,styles,icons,banners,images} into system/; each domain's
  templates, templates/styles, icons, images/banners, images into system/. Never overwrite:
  identical files are dropped, different ones kept as <name>-<domain>; a differing icon pack
  is kept whole as <pack>-<domain>.
- Campaigns: domains/*/campaigns/<folder> and campaigns/data-campaign-<slug> move to
  campaigns/<slug> (clash: <slug>-<domain>, then -2, -3...). Rebuild campaigns.json and write
  campaign.json with formerDomain and migratedFrom.
- datasets/ and backups/ move into system/.
- Leftovers (domains.json, domain.json, branding.json, anything else) are archived to
  system/legacy/v0.83/. Nothing is deleted.
- Write system/migration-v0.84-<time>.log and the layout marker. Print a summary of clashes
  and renames. If any step throws, log it, print where the backup is, and stop startup; the
  next start resumes.
- Moves use rename with a copy+delete fallback (different drive or Windows file locks).

Password recovery:
- Stop the server and remove the admin entry from system/users.json; a default
  admin / blackquill account is recreated at startup when no admin-role account exists.

Install, run and debug scripts are unchanged from v0.82 (install.bat, runme.bat,
runme-debug.bat, --debug, BLACKQUILL_DEBUG).

package-lock.json files must resolve from https://registry.npmjs.org/ only.

V0.86 FORGOTTEN REALMS WIKI LOOKUP + IMPORT (SUPERSEDES THE OLD HTML-SCRAPING IMPORT):
- Source: https://forgottenrealms.fandom.com (Fandom, MediaWiki). Use only its API, https://forgottenrealms.fandom.com/api.php (format=json, formatversion=2), with a BlackQuill User-Agent and a 15 s timeout. Code: server/lib/fandom.js, routes in server/routes/import.js; both need a login (401 otherwise).
- GET /api/import/forgotten-realms/lookup?name= -> { query, exact: {title,url,disambiguation} | null, suggestions: [{title,url,snippet}] (max 6) }.
  - exact: action=query&titles=<name>|<Title Case name>&redirects=1&prop=pageprops&ppprop=disambiguation; first page in namespace 0 that is not missing (redirects resolved, so "Elminster" finds "Elminster Aumar").
  - suggestions, in this order, de-duplicated and excluding the exact page: the search spelling suggestion (searchinfo.suggestion) if that page exists, then action=opensearch (namespace 0, redirects=resolve, limit 5), then action=query&list=search (srwhat=text, limit 6, snippet as plain text).
- GET /api/import/forgotten-realms?url=<wiki article URL> | ?name= -> { title, url, content, facts, images, wikiSource }. Writes nothing.
  - URL must be forgottenrealms.fandom.com/wiki/<Title> (or index.php?title=); https:// optional; #fragment and ?query ignored; non-article namespaces (File:, Category:, Special:, Template:, User:, Talk: ...) rejected with 400.
  - Text: action=parse&page=<title>&prop=text|images&redirects=1. Convert the HTML to Markdown: portable infobox data rows -> "## Quick Facts" bullet list (max 14); paragraphs, h2-h4 headings, ul/ol lists, blockquotes, bold/italic kept; links become plain text; remove references (<sup>), edit links, TOC, navboxes, message boxes, tables, figures and galleries; skip whole h2 sections named Appearances, Gallery, Further reading, References, Notes, External links, Connections, See also, Footnotes, Sources, Bibliography, Trivia and notes; drop empty headings. Decoded text has < and > escaped again (the reader renders Markdown with HTML on).
  - content = Quick Facts (v0.86.1: no "Imported from" line in the text; the reader shows it from wikiSource) + article + "## DM Notes" + "## Source" with the attribution line: article title linked to its URL, import date, "Licensed under CC BY-SA 3.0" linked to https://creativecommons.org/licenses/by-sa/3.0/, "see the article history for its authors", images keep their own licences on each file page, not affiliated with Fandom or Wizards of the Coast.
  - wikiSource = { site: "Forgotten Realms Wiki", title, url, license: "CC BY-SA 3.0", licenseUrl, importedAt }.
  - images: files from parse.images that are jpg/jpeg/png/webp/gif and not icons/logos/symbols/flags/placeholders; prop=imageinfo&iiprop=url|size|mime&iiurlwidth=1200; keep both sides >= 150 px; max 8, in page order. Each { sourceUrl (1200px thumb or original), previewUrl, file ("wiki-<slug>.<ext>", unique), caption (figure caption from the article, else the file name), filePage (the File: page URL) }. Only https://static.wikia.nocookie.net URLs are accepted.
